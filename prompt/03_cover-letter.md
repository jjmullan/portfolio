# 자기소개서

# 지원 동기

홍보・마케팅 실무에서 고객 니즈 기반의 기획 콘텐츠로 성과를 냈던 경험에서 ‘고객 중심적 사고’의 중요성을 배웠습니다. 특히, 웹 개발 기술로 실제 고객의 정보 탐색 문제를 해결했던 경험에서 프론트엔드 개발자로서의 진로를 선택하게 되었고, 이후 ‘무엇을 만들지’보다 ‘왜 만들어야 하는지’를 먼저 고민하는 사고방식을 갖게 되었습니다.

이러한 관점은 세 번의 사이드 프로젝트 기획의 밑바탕이 되었습니다. 그중 ‘상영시작후입장불가’의 경우 예매처가 파편화되어 통합 상영 정보 탐색에 어려움을 겪는 실제 사용자의 불편함에 집중하였습니다. 전국 영화관 상영 정보를 한눈에 확인할 수 있는 기능을 구현한 결과, “예매처가 분리되어 불편했는데 유용하게 사용하겠다”는 사용자의 공감을 이끌어냈습니다.

AI 기술의 발전으로 누구나 아이디어만 있다면 빠르게 제품을 출시할 수 있게 되었습니다. 이러한 산업의 변화 속에서 개발자에게 사용자의 문제를 명확히 정의하고, 이를 자사의 제품으로 해소하는 ‘문제 해결 능력’은 더욱 중요해질 것입니다. 홍보・마케팅 실무에서 다져온 고객 중심 사고와 기획 역량으로 사용자의 문제를 해결해온 위 경험을 바탕으로, 귀사와 함께 사용자의 여정에 깊이 관여하는 개발자가 되겠습니다.

# 개발 중 마주한 기술적 난관과 해결 방법

## 유저 플로우를 최우선으로 고려한 서버 상태 관리 전략

사이드 프로젝트 ‘상영시작후입장불가’ 개발 과정 도중 서버로부터 공급받는 데이터를 어떤 방식으로 제공할 것인가에 대해 고민한 경험이 있습니다. 하나의 페이지에 정규화된 테이블의 분산된 데이터들이 일괄 공급되어야 했기에, 사용자 경험을 저해하지 않으면서 동시에 조회 성능을 높이는 방식을 고민해야 했습니다.

처음에는 Prefetch 와 Pagination 을 활용하여 네트워크 병목을 줄이고, 페이지 이동 시 완성된 화면을 보여줌으로써 사용자 경험을 향상시키고자 했습니다. 페이지 전환 시 영화 목록, 포스터 이미지, 상영 정보 등 파편화된 테이블의 복합 데이터가 함께 제공되어야 했고, Prefetch 가 완료되기 전까지 페이지 전환이 지연되면서 되려 3000ms 이상의 대기시간이 발생했습니다. 쿼리 키 구조를 점검하고, Supabase 의 Index, Function 를 도입하여 조회 성능을 개선할 수는 있었지만, 페이지 이동 전 대기 문제를 완전히 해결하기는 어려웠습니다.

모바일 기반 서비스는 빠르고 즉각적인 응답을 제공할 때 사용자 경험에 긍정적인 영향을 미친다고 판단했습니다. 이에, Prefetch 중심 데이터 로딩 구조를 롤백하고 페이지 이동 후 서버 상태에 따른 Fallback UI 를 명확하게 제공하는 방식으로 개선했습니다. 쿼리 키를 페이지네이션 단위, 정렬 조건, 검색 조건으로 세분화하고, 이를 URL 쿼리 스트링과 동기화하여 사용자 탐색 상태가 유지되도록 하였습니다. 다중 쿼리 키 패턴으로 관리 복잡도가 높아짐에 따라, 각 entities 레이어에 쿼리 키 상수 파일을 두고 이를 shared 레이어에서 통합 관리하는 구조로 개선했습니다. 그 결과, 클릭 후 179 ms 만에 페이지가 전환되고, 평균 202 ms 로딩 피드백을 제공하며, 413 ms 내로 영화 목록의 주요 콘텐츠가 노출되도록 구현하게 되면서 사용자 경험과 조회 성능을 동시에 높일 수 있었습니다.

이처럼 서비스의 데이터 흐름과 비즈니스 특성에 대한 이해를 바탕으로 사용자의 연속적인 서비스 경험을 설계하고 개선하는 개발자가 되겠습니다.

# 프로젝트를 완수하기 위해 노력한 경험

## 학습 동기와 실행력으로 프로젝트 성공을 이끌다

⟪함께 자라기: 애자일로 가는 길⟫, ⟪출근했더니 스크럼 마스터가 된 건에 관하여⟫를 읽고 팀의 생산성을 높이는 협업 문화와 개발 방식에 대해 관심을 갖게 되었고, 특히 Agile 의 짧고 반복적인 개발 주기와 회고를 통한 지속적 개선 방식에 흥미를 갖게 되었습니다.

부트캠프 파이널 프로젝트에서 PM으로 참여하게 되면서, 팀 협업 문화를 도입할 수 있는 기회가 주어졌습니다. 스크럼 조직에서 합의된 방향으로 진행되지 않았을 때 되려 비효율을 초래하고 체계가 무너진다는 것을 배웠기에, 팀원들에게 도입하려는 이유와 방법에 대해 설명하고 팀원 모두의 동의를 얻어 진행하게 되었습니다.

5주의 프로젝트 기간을 7일 단위의 스프린트로 구분하여 관리하였고, 프로덕트 백로그를 우선순위에 맞게 주차별 스프린트 목표로 설정하여 MVP 를 달성하고자 했습니다. 매일 9시 30분에 데일리 스크럼을 진행하여 작업 진행 상황을 동기화하였고, 짝 프로그래밍을 통해 기능 구현 과정에서의 병목을 빠르게 해결하고자 했습니다. 각 스프린트 종료 시 회고를 통해 협업 과정과 개발 프로세스를 돌아보고 개선점을 도출했으며, 배포 후 QA 를 수행하여 실제 환경에서 기능과 사용자 플로우를 검증하고 발견된 이슈를 다음 스프린트에 반영했습니다.

적극적인 소통과 지속적인 개선 방식을 바탕으로 프로젝트를 진행한 결과, 4차 스프린트만에 MVP 개발을 완료하며 부트캠프 강사로부터 “프로젝트 시작부터 가장 소통이 원활하고 활발한 팀”이라는 평가를 받았습니다. 프로젝트 종료 후 동료평가에서 “체계적으로 계획하고 이를 꾸준히 실행하는 모습이 인상적이었다”, “프로젝트에 잘 참여할 수 있도록 분위기를 만들어 주었다”는 말을 들을 수 있었고, ‘좋은 코드를 작성하는 것만큼 팀원이 함께 일할 수 있는 조직 문화를 만드는 일도 중요하다’는 것을 배웠습니다.

앞으로도 팀이 같은 목표를 갖고, 소통하여 꾸준히 개선해나가는 ‘과정 중심’의 성과를 만들어내고 싶습니다.

# 개발자를 선택하게 된 이유

## 개발지식 없이 만든 홈페이지로 MAU 1만 명을 달성하다

영화제 홍보 매니저 근무 당시, 영화제 출품 자격에 관한 유선 문의가 하루 2회 이상 발생하면서 팀원들의 피로도가 누적되고 있다는 것을 파악했습니다. 기존 홍보 창구인 SNS 와 보도자료만으로는 정보 제공이 원활하지 않다고 판단했고, 파편화된 정보를 전달하는 기존의 방식이 아닌 누구나 쉽게 영화제명만 검색하더라도 통합된 정보를 획득할 수 있도록 웹 페이지 구축을 제안하게 되었습니다.

처음에는 아임웹, 워드프레스 등 홈페이지 제작 서비스를 활용해보고자 했습니다. 영화제 홍보를 총괄하며 다양한 업무를 병행해야 했기에, 별도의 제작 도구를 익히고 활용하는 데 많은 시간을 할애할 수 없었습니다. 무엇보다 빠른 출시와 낮은 러닝 커브가 중요하다고 판단했고, 이에 Notion 에 Oopy 를 결합한 방식으로 페이지 제작을 결정했습니다. 짧은 시간 안에 제작할 수 있으며 HTML 코드 블럭을 조합한 다양한 리치 미디어 삽입, GA 추적 등이 가능했기에 최적의 선택이라고 판단했습니다. 이를 바탕으로 2주만에 영화제 출품 자격을 비롯한 영화제 소개, 역대 영화제 상영작, 수상작 등을 아카이빙한 공식 홈페이지를 정식 배포하게 되었습니다.

배포 이후 기존 홍보 채널에서 공식 홈페이지를 지속적으로 안내하고, Naver 검색광고와 Meta Paid 광고의 랜딩페이지로 설정하여 트래픽을 집중시켰습니다. 그 결과, 월간 이용자 수 1만 명을 돌파하며 영화제 정보 전달의 핵심 통로로 자리잡을 수 있었고, 반복된 유선 문의 또한 주 1회 수준으로 크게 감소하며 팀원들의 부담을 크게 줄일 수 있었습니다.

웹 페이지를 직접 개설하여 사용자 문제를 해결하는 과정에 큰 흥미를 느꼈고, 이를 계기로 프론트엔드 개발자의 진로를 선택하게 되었습니다.
