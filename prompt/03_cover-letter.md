# 자기소개서

## 1. 개발자를 선택하게 된 이유

### Notion + Oopy 로 만든 홈페이지, MAU 1만 명을 달성하다

홍보 매니저로 근무했던 당시, 영화제 출품 자격에 관한 유선 문의가 하루 2회 이상 반복 발생하여 팀원들의 업무 피로도가 증가하고 있었습니다. SNS 게시물과 보도자료를 통한 기존의 정보 전달 방식으로만으로는 해결할 수 없다고 생각했고, 문제를 해결하기 위한 방법으로 영화제 정보를 한곳에 모아 제공하는 웹사이트 구축을 제안했습니다.

imweb, WordPress 등 대표적인 홈페이지 제작 서비스를 직접 사용해보며 검토한 결과, 러닝 커브로 빠른 출시가 불가하고 디자인 톤앤매너를 유지하는 데 제약이 있다고 판단했습니다. 대신 기존에 사용하던 Notion 에 Oopy 의 HTML 코드 블럭을 조합하는 방식을 제안하여 2주 만에 홈페이지를 정식 배포하였습니다. 그 결과, 문의 횟수가 주 1~2회 수준으로 감소하면서 팀원의 피로도를 크게 줄일 수 있었습니다. 더 나아가 Meta, Naver Paid 광고를 집행하여 홈페이지로의 유입을 집중시키는 전략으로 MAU 10,000명을 달성하며 영화제 정보 전달의 핵심 통로로 자리잡게 되었습니다.

웹 서비스를 직접 만들고 사용자 문제를 해결하는 과정에 큰 흥미를 느꼈고, 이를 계기로 프론트엔드 개발자의 진로를 선택하게 되었습니다.

## 2. 프로젝트를 완수하기 위해 노력한 경험

### 팀의 성공을 이끈 프로젝트 관리 능력

개발자 매거진 ⟪readIT⟫과 서적 ⟪함께 자라기⟫, ⟪출근했더니 스크럼 마스터가 된 건에 관하여⟫를 통해 Agile 방법론의 개념과 실행 방식을 접하게 되었고, 협업 구조와 팀의 작업 방식이 개발 생산성에 미치는 영향에 관심을 갖게 되었습니다. 부트캠프에서 진행한 두 번의 팀 프로젝트에서 Daily Scrum 을 통한 일별 작업 흐름 관리를 경험할 수 있었지만, 프로젝트 전반에 걸친 협업 방식으로 구조화하지 못한 점이 아쉬웠습니다.

부트캠프 파이널 프로젝트에서 PM으로 참여하면서 협업 구조를 직접 설계하고 운영할 수 있는 기회가 주어졌습니다. 체계적인 개발 진행 상황 관리와 팀원 간 자유롭고 자발적인 소통을 통해 팀의 목표를 달성하고자 했습니다.

가장 먼저, FigJam 을 활용한 Scrum 온보딩 자료를 제작, 실습 형태로 진행하여 팀원들이 프로젝트의 진행 방식을 쉽게 이해할 수 있도록 하였습니다. User Story 기반 프로덕트 백로그를 작성하여 우선순위를 정리하고, 총 5차의 스프린트 기반 개발 사이클을 관리했습니다. Daily Scrum 을 통해 작업 진행 상황을 동기화했으며, Pair Programming 을 도입하여 같은 Pair에서 1차 코드 리뷰를 진행한 뒤 다른 Pair가 Pull Request 를 검토하는 방식으로 팀원 모두가 코드를 확인할 수 있는 점검 체계를 구축했습니다. 스프린트 종료일에는 팀원 모두가 참여하는 Sprint Review 를 통해 개발된 기능을 점검하고, 검증된 코드를 지속적으로 통합, 배포했습니다. 배포 이후에는 개선 사항을 정리하고 다음 스프린트 시작 전 리팩토링을 진행하여 의도치 않은 오류를 예방했습니다. 기능 개발이 마무리되는 3차, 4차 스프린트에는 타 팀 개발자들과 Cross Testing 을 진행하여 사용자 관점에서 서비스 흐름을 검증하였습니다. 그 결과, 전체 팀 중 가장 빨리 기능 개발이 완료된 팀으로서 “가장 소통이 잘 된 팀”이라는 평가를 받았습니다.

이러한 경험을 통해 협업 구조 설계가 개발 생산성과 팀 커뮤니케이션에 직접적인 영향을 준다는 것을 몸소 깨달았습니다.

## 3. 어려운 문제를 해결한 경험

### 자체 설문조사를 통해 소비자의 탐색비용을 줄이다

온라인 패션 커뮤니티 활동 중 뉴발란스 운동화의 사이즈 문의 글이 하루 평균 3~4건 이상 반복적으로 업로드되는 것을 발견했습니다. 많은 사람들이 구매 전 사이즈 선택에 어려움을 겪고 있었지만, 댓글로 제공되는 조언은 개인 경험에 의존한 주관적인 정보가 대부분이었습니다. 특히 뉴발란스는 성별, 발볼 너비, 선호하는 실루엣에 따라 체감하는 사이즈에 차이가 있어, 소비자들이 구매 전 탐색 과정에서 불필요한 시간과 비용을 지불하고 있다는 문제를 인지했습니다.

이에 실제 구매자들의 데이터를 수집, 분석하여 누구나 참고할 수 있는 객관적인 사이즈 가이드를 제작하고자 했습니다. 개인 경험에 의존한 주관적인 조언을 최소화하고, 수치 기반 데이터를 통해 신뢰도 높은 정보를 제공하고자 했습니다.

먼저 설문 구조를 체계적으로 설계했습니다. 구매 여부 문항을 배치하여 실제 구매 경험이 없는 응답을 배제하였습니다. 평소 신는 정사이즈, 발볼 너비, 선호하는 착용감 등 사이즈 선택에 영향을 미치는 요소를 수치화된 선택지로 구성해 응답의 객관성을 높였습니다. 설문을 최종 배포하기 전 커뮤니티 내에서 파일럿 테스트를 진행해 문항의 이해도와 유효성을 점검하고 일부 질문을 수정했습니다. 완정된 설문지로 설문을 진행한 결과, 수집된 237개의 응답 중 데이터 신뢰도가 높은 105개의 표본을 선별하였습니다. 해당 결과를 차트와 그래프로 시각화해 누구나 직관적으로 이해할 수 있는 형태로 정리해 커뮤니티에 공유했습니다.

그 결과, 해당 게시물은 커뮤니티 평균 조회수의 약 10배에 해당하는 6,700회의 조회수와 91개의 좋아요를 기록했습니다. 또한 “구매 전에 이 자료를 참고했다”는 사용자 피드백이 이어지며 커뮤니티 내에서 필독 정보로 자리 잡았습니다.

이 경험을 통해 문제의 본질을 관찰하고, 데이터를 기반으로 해결책을 설계하는 과정의 중요성을 체감했으며, 사용자의 관점에서 실질적인 가치를 제공하는 문제 해결 역량을 키울 수 있었습니다.
